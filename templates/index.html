JSON Relational Duality View의 가치

기존 방식: DB 테이블 → 백엔드(JOIN SQL 작성) → API 엔드포인트 → JSON 변환 → 프론트엔드

ETag 기반 동시성 제어 (Lock-Free)

Oracle Duality View의 동시성 제어 — 왜 다른가?

Duality View의 모든 JSON 문서에는 _metadata.etag가 자동 포함됩니다.
ETag(Entity Tag)는 문서의 "버전 해시"로, 문서가 수정될 때마다 새로 발급됩니다.
이를 통해 락(Lock) 없이 동시 수정 충돌을 감지합니다 (낙관적 동시성 제어).

MongoDB (앱에서 직접 구현)
ETag를 DB가 제공하지 않음.
개발자가 version 필드를 만들고,
앱 코드에서 조건부 업데이트를 직접 구현해야 함.
Oracle Duality View (DB가 자동 관리)
DB가 ETag를 자동 생성·비교·갱신.
REST PUT만 하면 충돌 자동 감지.
@nocheck로 특정 필드 제외 가능.
동작 원리: User A가 문서 조회(ETag: abc) → User B도 조회(ETag: abc) → User A 수정 성공(새 ETag: def 발급) → User B 수정 시도 → ETag 불일치 → 실패 (Lost Update 방지)

Lock-Free Column Value Reservations

Lock-Free Reservations — 기존 방식과 무엇이 다른가?

숫자 컬럼에 RESERVABLE 속성을 지정하면, 여러 트랜잭션이 같은 행의 같은 컬럼을 동시에 차감/추가할 수 있습니다.
기존에는 한 트랜잭션이 행을 잠그면 다른 트랜잭션은 대기해야 했습니다.

기존 방식
Session A가 UPDATE → Session B 대기(블로킹) → A 커밋 후 B 진행
Lock-Free Reservations
Session A, B, C 동시 차감 가능. CHECK 제약으로 잔액 부족 시만 실패.

동시 차감 시뮬레이션 (계좌 잔액)

RESERVABLE 컬럼이 있는 계좌 테이블에서 여러 세션이 동시에 잔액을 차감하는 시나리오입니다.

Priority Transactions

Priority Transactions — 26ai 신기능

트랜잭션에 우선순위(HIGH / MEDIUM / LOW)를 부여합니다.
높은 우선순위 트랜잭션이 낮은 우선순위에 의해 블로킹되면, DB가 자동으로 낮은 우선순위 트랜잭션을 롤백합니다.

기존 방식
VIP든 일반이든 먼저 잠근 쪽이 우선. 중요한 트랜잭션이 대기할 수 있음.
Priority Transactions
HIGH가 LOW에 블로킹되면, 대기 시간 초과 후 LOW 자동 롤백 → HIGH 진행.
ALTER SESSION SET TXN_PRIORITY = HIGH | MEDIUM | LOW

우선순위 충돌 시뮬레이션

LOW 트랜잭션이 행을 잠근 상태에서 HIGH 트랜잭션이 같은 행을 요청하는 시나리오입니다.
