## 1. 구동 구조

이 앱은 **macOS launchd 로 상시 구동**됩니다. 로그인하면 자동으로 뜨고, 죽으면 다시 뜹니다.

| 항목 | 값 |
|---|---|
| 서비스 이름 | `com.db26ai.server` |
| 포트 | **8247** |
| 정의 | `deploy/com.db26ai.server.plist` (`RunAtLoad` + `KeepAlive`) |
| 설치 위치 | `~/Library/LaunchAgents/com.db26ai.server.plist` |
| 로그 | `db26ai.log` (프로젝트 루트, gitignore) |
| 실행 | `venv/bin/python main.py` |

> **`main.py` 는 `reload=True` 지만 launchd 로 뜬 프로세스에는 기대하지 마세요.**
> 코드 변경 후에는 **반드시 수동 재기동**합니다.

### 설치 · 해제

```bash
deploy/install-launchd.sh     # 등록 + 즉시 기동 (기존 프로세스·8247 점유 정리 포함)
deploy/uninstall-launchd.sh   # 해제
```

### 수동 실행 (개발 중)

```bash
./run.sh        # 포그라운드 (Ctrl+C 로 종료)
./run-bg.sh     # 백그라운드 (db26ai.pid 생성)
./stop.sh       # run-bg.sh 로 띄운 것 종료
```
launchd 가 떠 있는 상태에서 이걸 쓰면 포트가 충돌합니다. 하나만 쓰세요.

## 2. 일상 운영 명령

```bash
# 재기동 (코드 변경 후 필수)
launchctl kickstart -k gui/$(id -u)/com.db26ai.server

# 상태 확인 — DB·프로필·문서·ONNX·벡터인덱스를 한 번에
curl -s http://localhost:8247/api/health | python3 -m json.tool

# 로그
tail -f db26ai.log

# 서비스 등록 여부
launchctl list | grep db26ai
```

### 재기동 후 기다릴 것

```
✓ 데이터베이스 연결 풀이 초기화되었습니다.
✓ Vector Search 테이블이 초기화되었습니다.
✓ ADB Keepalive 스케줄러가 시작되었습니다 (매주 월 09:00).
INFO:     Application startup complete.          ← 화면은 여기서 이미 열린다
✓ 커넥션 풀 워밍 완료: 5/5개 (…, 15000ms)     ← 벡터 검색은 여기서부터 제 속도
```

**워밍이 끝나기 전 첫 벡터 질의는 5초쯤 걸립니다.** 장애가 아닙니다 —
ONNX 임베딩 모델을 커넥션마다 최초 1회 로드하기 때문이며, 워밍이 그걸 미리 해둡니다.
시연 직전에 재기동했다면 **15초 기다렸다가** 시작하세요.

## 3. 배포 절차

관찰 가능한 변경이면 이 순서를 지킵니다.

```bash
# 1. 검증
./venv/bin/python -m pytest tests/ -q     # 서버 없으면 통합은 자동 skip
./venv/bin/ruff check .

# 2. 운영 반영
launchctl kickstart -k gui/$(id -u)/com.db26ai.server

# 3. 스모크 (워밍 대기 후)
curl -s http://localhost:8247/api/health
#   → 바꾼 탭의 대표 엔드포인트도 한 번 호출

# 4. 커밋 (시크릿 게이트 필수 — 저장소가 GitHub 공개다)
git add <files>
scripts/check-secrets.sh || exit 1
git commit && git push
```

### ⚠ 프론트를 고쳤다면 `?v=N` 을 올리세요

`templates/index.html` 안의 `style.css?v=N`·`app.js?v=N` 버전을 **반드시 증가**시킵니다.
안 올리면 브라우저가 캐시된 옛 파일을 그대로 씁니다 — **"고쳤는데 화면이 안 바뀐다"의 단골 원인**입니다.

### 일회성 DB 작업

`/api/execute-sql` 은 SELECT 로 시작하는 문장만 받습니다(`WITH` CTE 도 거부).
DDL·DML·CTE 가 필요하면 스크립트로 돌립니다.

```bash
# 반드시 프로젝트 루트 cwd — .env 로딩에 필요
./venv/bin/python <스크립트>
```
스크립트는 `init_pool()` → 작업 → `close_pool()` 패턴을 씁니다.
셋업용 SQL 은 `sql/setup/` 에 번호를 붙여 남깁니다(재현 가능하게).

## 4. 데이터베이스 운영

| 항목 | 값 |
|---|---|
| DSN | `db26aidemo_medium` (Autonomous DB) |
| 스키마 | `ADMIN` |
| Wallet | `~/Dev/Wallet_DB26AIDEMO` (`.env` 의 `ORACLE_WALLET_DIR`) |
| 커넥션 풀 | min=1 / max=5, DB call 타임아웃 120초 |

### ADB Keepalive — 인스턴스 회수 방지

OCI Always Free ADB 는 **일정 기간 미사용 시 회수**됩니다.
그래서 `app/scheduler.py` 가 주기적으로 `SELECT 1` 핑을 보냅니다.

| 잡 | 주기 |
|---|---|
| `adb_keepalive_initial` | 기동 직후 1회 |
| `adb_keepalive_weekly` | **매주 월요일 09:00** |

로그에서 `[keepalive] ✅ ADB 핑 성공` 을 확인할 수 있습니다.

> **맥이 오래 잠들어 있으면 이 잡도 돌지 않습니다.** 장기간 자리를 비울 계획이면
> 돌아온 뒤 `/api/health` 로 DB 연결을 먼저 확인하세요.

### 스키마 재구성

`sql/setup/` 에 번호순 스크립트가 있습니다. 새 테넌시로 옮길 때 순서대로 실행합니다.

| 파일 | 내용 |
|---|---|
| `41.aidb_to_26aidemo_mig.sql` | 구 테넌시 → 신 테넌시 Data Pump export |
| `42.create_new_26aidemo.sql` | import + Network ACL + Credential + Select AI 프로필 + ONNX 로드 |
| `50_oracle_text_index.sql` | 전문검색 인덱스 (`WORLD_LEXER`, `SYNC ON COMMIT`) |
| `onnx_db_load.sql` · `selectAI_*.sql` | ONNX 적재 · Select AI 설정 참고 |

> **공개본에는 자격증명이 자리표시자(`<...>`)로 들어 있습니다.**
> 실제 값이 든 원본은 `sql/setup/_private/`(gitignore)에 있습니다.

## 5. 백업

이 앱은 **데모용이라 영속 데이터가 거의 없습니다.** 진짜로 지켜야 할 것만 정리합니다.

| 대상 | 백업 방법 | 잃으면 |
|---|---|---|
| **`.env`** | 별도 안전한 곳에 사본 | 접속 불가. **git 에 절대 넣지 말 것** |
| **Wallet 디렉터리** | 〃 (또는 OCI 콘솔에서 재발급) | DB 접속 불가 |
| `sql/setup/_private/` | 〃 | 이관 절차 재작성 필요 |
| 소스·문서 | **git (GitHub 원격)** | — |
| SH 샘플 데이터 | 재적재 가능 (Data Pump) | 재적재 |
| 업로드 PDF·벡터 | 재업로드 가능 | 재업로드 (27쪽 기준 30초) |

**요컨대 `.env` 와 Wallet 만 잘 챙기면 나머지는 복구 가능합니다.**

## 6. 모니터링 · 정기 점검

### 매번 (시연 전)

```bash
curl -s http://localhost:8247/api/health | python3 -m json.tool
```
`database_connected: true` · `profile_count ≥ 1` · `embedded_count > 0` 확인.
시연 직전 재기동했다면 **워밍 15초** 기다립니다.

### 주기적으로

| 주기 | 확인 |
|---|---|
| 주 1회 | 로그의 `[keepalive] ✅ ADB 핑 성공` — ADB 회수 방지가 도는지 |
| 월 1회 | `./venv/bin/python -m pytest tests/ -q` — 회귀 없는지 |
| 월 1회 | `scripts/check-secrets.sh --tracked` — 시크릿이 새어 들어가지 않았는지 |
| 변경 시 | `docs/SESSION_HANDOFF.md` 3절 스냅샷을 실제와 대조 |

### 로그에서 봐야 할 것

| 패턴 | 뜻 |
|---|---|
| `✓ 커넥션 풀 워밍 완료: 5/5개` | 정상. 5/5 가 아니면 커넥션 확보 실패 |
| `[keepalive] ✅ ADB 핑 성공` | ADB 유지 정상 |
| `[health] … 조회 실패` | `/api/health` 일부 항목 실패 (예전엔 조용히 숨었다) |
| `[upload] 임베딩 저장 실패` | 임베딩이 저장되지 않음 — 모델 차원과 HNSW 인덱스 불일치 의심 |
| `[hybrid] CONTAINS 실패 → LIKE 폴백` | Oracle Text 인덱스 문제 |

> 2026-09-04 이전에는 이 경고들이 `except: pass` 에 묻혀 **아무것도 로그에 남지 않았습니다.**
> 지금은 실패하면 반드시 로그에 뜹니다 — 로그가 조용하면 정상이라는 뜻입니다.
