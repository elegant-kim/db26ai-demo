## 1. 서버가 안 뜬다

### 증상: 브라우저에서 연결 거부

```bash
launchctl list | grep db26ai        # 없으면 서비스 미등록
deploy/install-launchd.sh           # 등록 + 기동
launchctl kickstart -k gui/$(id -u)/com.db26ai.server
tail -40 db26ai.log                 # 기동 실패 사유
```

### 증상: 포트 8247 이 이미 사용 중

`run.sh`/`run-bg.sh` 로 띄운 프로세스와 launchd 가 **동시에** 떠 있을 때 납니다.

```bash
lsof -ti:8247          # 점유 프로세스 확인
./stop.sh              # run-bg.sh 로 띄운 것 정리
# 또는
kill -9 $(lsof -ti:8247) && launchctl kickstart -k gui/$(id -u)/com.db26ai.server
```

### 증상: 기동은 됐는데 `/api/health` 가 느리거나 실패

기동 직후 **15초간** 커넥션 풀 워밍이 돕니다. 그 사이 첫 요청이 느릴 수 있습니다.
로그에 `✓ 커넥션 풀 워밍 완료: 5/5개` 가 뜬 뒤에 다시 확인하세요.

## 2. DB 에 연결이 안 된다

### 증상: `database_connected: false`

| 원인 | 확인 · 조치 |
|---|---|
| **ADB 가 STOPPED** | OCI 콘솔에서 인스턴스 상태 확인 → START |
| **ADB 가 회수됨** | Always Free 는 장기 미사용 시 회수됩니다. 로그에서 마지막 `[keepalive] ✅ ADB 핑 성공` 시각 확인 |
| Wallet 경로 오류 | `.env` 의 `ORACLE_WALLET_DIR` 이 실제 디렉터리인지 |
| Wallet 만료 | OCI 콘솔에서 재다운로드 |
| 자격증명 변경 | `.env` 의 `ORACLE_USER`/`ORACLE_PASSWORD` |

> **맥이 오래 잠들어 있었다면 keepalive 잡도 돌지 않았습니다.**
> 장기간 자리를 비웠다 돌아왔다면 **가장 먼저 `/api/health`** 를 확인하세요.

### 증상: `DPY-4005` 풀 고갈

`pool.acquire()` 블록 **안에서 또 커넥션을 잡았거나**, 그 안에서 LLM·외부 API 같은
느린 작업을 기다리는 코드가 있습니다. SELECT 로 값만 받아 커넥션을 반납한 뒤 처리하세요.

## 3. NL2SQL 이 안 된다

### 증상: 질문하면 500, `ORA-20046: AI profile is not enabled in the session`

**2026-09-04 수정됨.** 원인은 이랬습니다 — `profile_name` 을 비워 `DBMS_CLOUD_AI.GENERATE`
를 호출하면 Oracle 이 **세션 프로필**로 폴백하는데, `SET_PROFILE` 은 세션 단위이고
커넥션 풀은 요청마다 다른 세션을 줍니다. `/api/set-profile` 을 호출해 둬도 다른 커넥션이
배정되면 실패했습니다. **커넥션 풀 워밍으로 커넥션이 5개가 되면서 확률이 오히려 올라갔습니다.**

지금은 `resolve_profile()` 이 항상 프로필 이름을 명시합니다.
**다시 나타난다면** 프로필이 하나도 없거나 전부 DISABLED 인지 확인하세요:
```bash
curl -s localhost:8247/api/profiles | python3 -m json.tool
```

### 증상: 질문이 간헐적으로 500 (위와 다른 메시지)

외부 LLM(Groq·Gemini) **무료 티어 한도**이거나 일시 장애입니다.
사이드바에서 다른 프로필로 바꿔 보세요. 로그에 원문 오류가 남습니다.

### 증상: 엉뚱한 컬럼으로 SQL 을 만든다

**Annotation 을 적용**해 보세요 (사이드바 → 참조 테이블 → Annotation 적용).
적용 전후 같은 질문을 비교하면 차이가 보입니다.

### 증상: SQL 직접 실행이 거부된다

`execute_raw_sql()` 은 **SELECT 로 시작하는 문장만** 허용합니다(보안).
`WITH` 로 시작하는 CTE 도 거부되니, 바깥을 `SELECT * FROM (…)` 로 감싸세요.
DDL·DML 이 필요하면 `./venv/bin/python` 스크립트로 돌립니다.

## 4. 벡터 검색이 이상하다

### 증상: 검색 결과가 0건

```bash
curl -s localhost:8247/api/health | python3 -c "
import sys,json; d=json.load(sys.stdin)
print('문서', d['doc_count'], '/ 청크', d['chunk_count'], '/ 임베딩', d['embedded_count'])"
```

| 결과 | 뜻 |
|---|---|
| 전부 0 | PDF 를 업로드하세요 |
| 청크 > 0, **임베딩 = 0** | 아래 "임베딩이 저장되지 않음" |
| 둘 다 > 0 인데 0건 | 질의어가 문서 내용과 무관하거나, 키워드 모드에서 문서에 없는 단어 |

### 증상: 업로드는 "성공"인데 임베딩이 저장되지 않음 (`ORA-51932`)

**가장 헷갈리는 장애입니다.** 로그에 이렇게 뜹니다:
```
[upload] 임베딩 저장 실패(이후 동일 오류는 생략): ORA-51932: Mismatched dimension count …
```

**원인**: `embedding VECTOR` 컬럼은 차원 무제약이지만 **HNSW 인덱스가 첫 데이터의 차원으로
고정**됩니다. 임베딩 모델을 차원이 다른 것으로 바꾸면(E5_BASE 768 ↔ E5_SMALL 384) 충돌합니다.

**조치** — 순서를 지켜야 합니다:
```
1. 기존 청크 삭제        DELETE FROM doc_chunks;  DELETE FROM documents;
2. HNSW 인덱스 DROP      DROP INDEX doc_chunks_hnsw_idx;
3. .env 의 EMBEDDING_MODEL 변경 → 서버 재기동
   (기동 시 인덱스가 비어 있는 상태로 자동 재생성됨)
4. PDF 재업로드          → 새 차원으로 인덱스가 고정된다
```

> **사이드바의 런타임 임베딩 전환은 이 절차를 밟지 않습니다** — 알려진 제약입니다.
> 전환 후 업로드하면 임베딩이 NULL 이 됩니다. 모델을 바꾸려면 위 절차를 쓰세요.

### 증상: 하이브리드 검색인데 keyword 점수가 전부 0

**2026-09-04 수정됨.** 자연어 문장을 `CONTAINS` 에 그대로 넣으면 `?` 등이 Oracle Text
예약 연산자라 `ORA-29902` 로 터지고 LIKE 로 폴백되는데, 문장 전체 LIKE 는 0건입니다.
결과적으로 **하이브리드가 이름만 하이브리드고 실제로는 벡터 전용**이었습니다.

지금은 `to_contains_query()` 가 ACCUM 구문으로 변환합니다
(`"인덱스를 … 하나요?"` → `"인덱스%, 효율%, 사용%, SQL, 작성%"`).
**다시 0이 나온다면** 질의어가 전부 불용어이거나(예: "그것은 무엇인가요") 문서에 없는 단어입니다.

### 증상: 키워드 검색이 9초 넘게 걸린다

Oracle Text 인덱스가 없어 `LIKE '%…%'` 로 폴백 중입니다(CLOB 전수 스캔).
확인 — 검색 결과의 `sql_executed` 에 `CONTAINS` 가 아니라 `LIKE` 가 보입니다.

```sql
SELECT index_name, index_type, status FROM user_indexes WHERE table_name = 'DOC_CHUNKS';
-- DOC_CHUNKS_TEXT_IDX (DOMAIN) 이 있어야 정상
```
없으면 `sql/setup/50_oracle_text_index.sql` 을 실행하세요. **CONTAINS 104ms vs LIKE 9,880ms** 차이입니다.

### 증상: 첫 검색만 5초, 이후는 빠르다

**정상입니다.** ONNX 임베딩 모델을 커넥션마다 최초 1회 로드합니다(E5_BASE 5.2초).
기동 시 워밍이 이걸 미리 하지만, 워밍이 끝나기 전에 질의하면 겪습니다. 15초 기다리세요.

### 증상: 검색이 3~4초 걸린다

**대부분 정상입니다.** SQL 자체는 0.1초 안팎이고 나머지는 **LLM 답변 생성** 시간입니다.
확인하려면 **비교 모드**로 검색해 보세요 — RAG 답변을 만들지 않아 40~70ms 에 끝납니다.

## 5. 그래프 · Duality 가 이상하다

### 증상: SQL 과 SQL/PGQ 결과가 다르다

**이 탭의 존재 이유가 "두 방식이 같은 결과를 낸다"이므로 반드시 같아야 합니다.**
2026-09-04 에 두 원인을 고쳤습니다:

| 원인 | 조치 |
|---|---|
| `ORDER BY` 가 없어 거대한 결과에서 임의의 10행씩 집어옴 | 결정적 정렬 추가 |
| PGQ 가 `ORA-49011` 로 0행 | `GRAPH_TABLE()` 안에서 집계 불가 → 바깥에서 집계 |

새 비교 쿼리를 추가할 때 **이 둘을 반드시 지키세요.** 회귀 테스트가 있습니다
(`pytest tests/test_api_smoke.py -k PropertyGraph`).

### 증상: 그래프 생성이 "이미 존재합니다"

정상 동작입니다. 정의를 바꿨다면 **삭제 후 재생성**해야 반영됩니다.
Property Graph 는 기존 테이블 위의 뷰라 삭제해도 데이터는 안전합니다.

### 증상: `ORA-22849: Type VECTOR is not supported`

`VECTOR` 컬럼에 집계함수를 직접 썼습니다. 이렇게 우회하세요:
```sql
COUNT(CASE WHEN embedding IS NOT NULL THEN 1 END)   -- COUNT(embedding) 은 안 됨
```

## 6. 화면이 이상하다

### 증상: 코드를 고쳤는데 화면이 안 바뀐다

**십중팔구 캐시입니다.** `templates/index.html` 의 `style.css?v=N`·`app.js?v=N` 버전을
올리지 않았습니다. 올리고 재기동하세요. 급하면 브라우저 강력 새로고침(⌘⇧R).

### 증상: 화면 일부가 비어 있다

브라우저 콘솔(F12)을 여세요. Vue 렌더 오류면 콘솔에 뜹니다.
API 쪽이면 Network 탭에서 어떤 요청이 실패했는지 확인합니다.

### 증상: 「매뉴얼」 탭에 문서가 안 보인다

문서 파일은 있는데 목록에 `available: false` 로 나온다면 **파일명 번호 prefix** 를 확인하세요.
`docs/guides/` 안에서 `01*`·`02*`·`03*`·`04*` glob 으로 찾습니다.
새 문서를 추가했다면 `app/routes.py` 의 `_GUIDE_WHITELIST` 에도 등록해야 합니다.

```bash
curl -s localhost:8247/api/guide/docs | python3 -m json.tool
```

## 7. 개발 중 자주 만나는 것

| 증상 | 원인 · 조치 |
|---|---|
| 스크립트가 `.env` 를 못 읽음 | **프로젝트 루트 cwd** 에서 `./venv/bin/python` 으로 실행 |
| 커밋이 시크릿 게이트에 걸림 | 실제 시크릿이면 자리표시자로 치환 후 원본은 `sql/setup/_private/`. 오탐이면 `scripts/check-secrets.sh` 의 제외 규칙 조정(근거를 주석으로) |
| `grep --include=*.py` 가 죽음 | zsh 글로브 문제. 대상 파일을 나열하거나 따옴표로 감쌀 것 |
| API 응답 파싱이 자꾸 빗나감 | 결과 배열 키가 엔드포인트마다 다릅니다(`data`/`chunks`/`sql_data`/`models`). **파싱 전에 키를 먼저 확인**하세요 — `docs/design/03_API_명세서.md` |
| 테스트가 전부 skip | 서버가 안 떠 있으면 통합 테스트는 자동 skip 됩니다. 단위 테스트만 돌아간 것이니 정상 |
