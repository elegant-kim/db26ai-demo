## 0. 시작하기

### 접속

**http://localhost:8247/** — 서버는 macOS launchd 로 상시 구동됩니다. 따로 띄울 필요가 없습니다.

화면이 안 뜨면:
```bash
launchctl kickstart -k gui/$(id -u)/com.db26ai.server
curl -s http://localhost:8247/api/health
```

> **재기동 직후 15초간**은 커넥션 풀 워밍(임베딩 모델 예열)이 백그라운드로 돕니다.
> 화면은 바로 열리지만, **첫 벡터 검색은 워밍이 끝난 뒤가 정확**합니다.
> 로그(`db26ai.log`)에 `✓ 커넥션 풀 워밍 완료` 가 뜨면 준비 완료입니다.

사이드바는 없습니다. **탭 = 상단 메뉴, 기능 = 서브탭, 결과 = 카드**이고, 어느 화면에서든 `⌘K`(또는 헤더 🔍)로 기능을 검색해 바로 이동합니다.
페이지 헤더 우상단의 **「장표 n」** 은 지금 화면에 연결된 발표 장표를 오른쪽 패널로 엽니다(덱이 준비된 경우에만 보입니다 — 매뉴얼 › 장표, `docs/slides/README.md`).
**헤더 오른쪽 상태칩이 이 앱의 계기판입니다.** 무언가 이상하면 여기부터 보세요 (칩을 호버하면 상세, 클릭하면 매뉴얼).

| 칩 | 정상값 | 이상하면 |
|---|---|---|
| DB | 초록 점 `DB` | ADB 가 멈췄거나 wallet 문제 — 회색/빨강 |
| 임베딩 | `ONNX · E5_BASE` | 모델을 바꿨다면 여기에 반영됩니다. Vector 탭 「임베딩 · ONNX」에서 인덱스와 다르면 경고 |
| LLM (넓은 화면) | `gemini-2.5-flash` | RAG 답변·AWR 분석에 쓰입니다 |

### 이 앱을 관통하는 하나의 서사

**모든 탭이 "같은 질문을 두 방식으로 풀어 나란히 놓고 비교"합니다.**
시연할 때 이 점을 먼저 말해두면 각 탭이 훨씬 잘 이해됩니다.

| 탭 | 비교 |
|---|---|
| NL2SQL | 사람이 쓴 SQL ↔ AI 가 생성한 SQL |
| Vector Search | 키워드 검색 ↔ 의미 검색 ↔ 둘을 합친 하이브리드 |
| Duality | 관계형 JOIN ↔ 같은 데이터의 JSON 문서 |
| Property Graph | 기존 SQL JOIN ↔ SQL/PGQ 그래프 질의 |
| 개발생산성 | 기존 잠금 방식 ↔ Lock-Free / Priority |

## 1. NL2SQL (Select AI)

**자연어로 물으면 Oracle 이 SQL 을 만들어 실행합니다.** LLM 이 앱이 아니라 **DB 안에서** 호출된다는 점이 핵심입니다.

### 이렇게 써보세요 — 서브탭 순서가 곧 시연 순서입니다

> 2026-10-01 재배치: **환경 → 스키마·Annotation → 질문 → 피드백·Few-shot → 이력**. 프로필이 무엇을 보는지(스키마)를 먼저 보고 질문한다.
> 질문 탭은 **2단**이다 — 왼쪽 「실행 설정」 패널(실행 모드 · 예시 질문/프리셋 · 대화 설정 · 도구)과 오른쪽 대화. 패널 오른쪽 위 아이콘으로 접으면 시연 중엔 대화만 보이고, 접은 상태는 브라우저가 기억한다.

**「환경」 (기본 진입) — 시연 전에 세팅을 보여줍니다**

1. 페이지 우상단 **AI 프로필** 셀렉트에서 프로필 선택 (기본 `GEMINI_SH_PROFILE` — 2026-09-07 현재 GROQ 프로필은 API 키 문제로 실패).
   세 서브탭이 같은 프로필을 봅니다.
2. 상태 스트립이 한 줄로 요약합니다 — 프로필 · 모델 · **크리덴셜 ✓/✗** · **ACL ✓/✗** · 참조 테이블 수 · Annotation 수
3. 카드 3개가 사슬입니다: **① 프로필**(어느 LLM 으로 어느 테이블을 보는가) → **② 크리덴셜**(프로필의 `credential_name`) → **③ 네트워크 ACL**(프로필의 `provider_endpoint` 호스트).
   각 카드의 「조회 SQL」을 펼치면 어느 뷰를 봤는지 나옵니다.
4. **실제 호출 테스트**를 한 번 누릅니다. 세 카드가 전부 ✓ 여도 키가 만료됐으면 여기서 실패합니다 —
   `ENABLED='TRUE'` 는 키가 *등록됐다*는 뜻이지 *유효하다*는 뜻이 아닙니다. 실패하면 ORA 코드 옆에 원인 힌트가 붙습니다.

**「질문」 — Select AI 본 시연**

5. **실행 모드**를 `showsql(SQL 보기)` 로 (7종 세그먼트 — 영문이 곧 `DBMS_CLOUD_AI.GENERATE` 의 action 값)
6. **예시 질문** 셀렉트에서 하나 고르거나 직접 입력 → `질문`
7. 답변 아래 후속 버튼 — `runsql`·`narrate`·`explainsql`·`실행계획`·`showprompt`·`차트` 로 같은 질문을 다른 모드로
   (한 번 받은 결과는 캐시돼 버튼이 빨간색으로 표시됩니다. `차트`·`실행계획` 만 한글인 이유: Select AI 액션이 아니라 앱 기능입니다)

### 멀티턴 대화 (2026-09-29)

질문 입력줄 아래의 **Multi Turn**(기본 ON)이 켜져 있으면 앞 질문·답을 이어받습니다 — "2000년 매출 상위 3개 제품" 다음에 "그중 1위 제품만 월별로" 라고 물으면 앞 답의 조건(2000년)이 그대로 따라옵니다. Oracle 이 DB 안에 대화 객체(`conversation_id`)를 만들고 앱은 그 ID 만 들고 다닙니다.

| 조작 | 뜻 |
|---|---|
| **이어서 질문하기** 체크 해제 | 이번 질문만 대화 없이 독립 실행 (대화는 보관) |
| **정상답변시 대화초기화** | 성공한 답변 뒤에 대화를 버리고 다음 질문은 새 대화로 — 답변 아래 안내 문구가 붙습니다 |
| **새 대화** | 지금 바로 새 conversation 으로 |
| 답변 아래 작은 글씨 | `conversation_id · elapsed · 액션 · 프로필 · 모델 · multi turn · log #` — 클릭하면 ID 복사. `log #` 은 이력 테이블(`AI_QUERY_LOG`)의 행 번호 |

입력은 여러 줄이 됩니다 — Enter 전송, Shift+Enter 줄바꿈. 다른 액션으로 이미 받아 둔 SQL·프롬프트는 답변 아래 「생성 SQL 보기」「프롬프트 보기」로 접혀 있습니다.

### 유통 시연용 샘플로 바꿔 시연하기 (2026-09-30)

페이지 우상단 프로필을 **`RETAIL_DEMO_PROFILE`** 로 바꾸면 제과 유통 데이터(매장·제품·진열현황·매출, `POC_*` 테이블)로 시연합니다 — 예시 질문 10건("면수별 전시상태별 매출 금액은?", "전시위치별 매출 상위 10개" …), Annotation 세트, 이력 필터가 전부 이 프로필 기준으로 바뀝니다. 진열 현황의 **진열위치 약 30% 가 「미입력」**이라 "진열위치별 매출" 을 그냥 물으면 미입력이 한 행으로 섞이고, "미입력인 것은 제외해줘" 를 붙이면 SQL 에 `<> '미입력'` 이 들어갑니다 — 데이터 품질과 질문의 정확성을 함께 보여주는 지점입니다. 적재·원복은 `sql/seed/retail_demo/README.md`.

### 답변 피드백 👍 / 👎 (2026-09-30)

답변 아래 「이 답변 평가」에서 **좋음/나쁨**을 고르고 사유(선택)를 적어 **저장**하면 두 곳에 남습니다 — Oracle 의 프로필 피드백 벡터 인덱스(`GEMINI_SH_PROFILE_FEEDBACK_VECINDEX`)와 앱의 `AI_FEEDBACK_LOG`. 다음에 **비슷한 질문**을 하면 Oracle 이 그 예시를 프롬프트에 자동으로 넣습니다(`showprompt` 로 보면 끝에 "examples of previous successful queries" 가 붙습니다). 👎 에는 「올바른 SQL 직접 제시」를 펼쳐 정답 SQL 을 같이 줄 수 있습니다.
저장에는 몇 초가 걸립니다 — 피드백은 실행된 `SELECT AI` 문장에만 붙기 때문에, 없으면 그 자리에서 한 번 실행합니다. 등록 뒤에는 배지로 보이고 연필로 수정(삭제 후 재등록), 휴지통으로 삭제합니다. 「이력」 탭의 상세에서도 같은 상자로 편집합니다. 「환경」 탭 상태 줄의 **「피드백 N건」** 배지와 프로필 카드의 `embedding_model` · `feedback_index` 가 준비 상태입니다 — `embedding_model` 이 없으면 저장이 `ORA-20048` 로 실패합니다.

### 새 프로필 만들기 · OCI Generative AI (2026-09-30)

「환경」 탭 상태 줄의 **「새 프로필 만들기」** 가 `DBMS_CLOUD_AI.CREATE_PROFILE` 을 폼으로 바꿔 줍니다 — provider(OpenAI 호환 · **OCI Generative AI** · Google · Anthropic · Azure …), 모델, 크리덴셜(유형이 API 키/OCI API Key/Resource Principal 로 표시), 볼 테이블, annotations 같은 플래그. 「미리보기」로 실행될 PL/SQL 을 확인하고 「실행」하면 환경 탭이 새 프로필로 바뀝니다. **OCI 는 region 이 필수**이고 한국 리전엔 GenAI 가 없어 오사카 등 제공 리전만 선택지에 있습니다. OCI 프로필은 환경 탭 ③ 카드가 `inference.generativeai.<region>.oci.oraclecloud.com` 을 ACL 과 대조하고, ① 카드에 region · oci_apiformat 이 보입니다. 「실제 호출 테스트」는 프로바이더에 관계없이 같은 chat 호출입니다.

### 프로필(모델) 비교 실행 (2026-09-30)

「질문」 탭 프리셋 줄의 **「프로필 비교」** 를 누르면 프로필 체크박스가 뜹니다. 2~3개를 고르고 실행하면 입력줄의 질문을 프로필마다 차례로 풀어 **모델 · 생성 SQL · 결과 앞 5행 · 생성 소요**를 한 열씩 보여주고, 가장 빠른 프로필에 배지가 붙습니다. 같은 테이블을 보는 프로필끼리 비교해야 뜻이 있습니다(보는 테이블이 다르면 경고). 누적 평균은 「이력」 탭의 「프로필(모델)별 소요」에 있습니다.

### 정확도 개선 시나리오 ①②③ (2026-09-30)

「질문」 탭 프리셋 줄 오른쪽 끝의 **「정확도 개선 시나리오」** 는 입력줄의 질문 하나를 세 조건으로 풀어 나란히 놓습니다 — ① Annotation 없이 → ② Annotation 적용 → ③ ②의 SQL 을 피드백으로 등록한 뒤 다시. 각 열에 생성 SQL · 결과 앞 5행 · 소요가 보이고, 아래 「프롬프트 diff」를 펼치면 ②와 ③ 의 `showprompt` 차이에서 **초록 줄 = 피드백으로 주입된 예시**가 드러납니다. Annotation 은 테이블을 건드리지 않고 프로필 속성 `annotations`·`comments` 를 잠시 끄고 켜며, 끝나면 원래 값으로 되돌리고 시나리오용 피드백도 지웁니다(1분 안팎, 실패해도 복원).

### Few-shot 일괄 등록 (2026-09-30)

다섯 번째 서브탭 **「피드백 · Few-shot」**. 시연자가 검증한 (질문, 정답 SQL, 설명) 파일을 올리면 미리보기가 뜨고, **「검증」**이 각 SQL 을 `EXPLAIN PLAN` 으로 확인(실행은 안 함)한 뒤 **「일괄 등록」**이 통과한 행을 positive 피드백으로 넣습니다. 행마다 `SELECT AI showsql` 이 한 번 돌아 수 초씩 걸리므로 진행률이 행 단위로 올라가고, 끝나면 「실패만 재시도」가 생깁니다. 파일은 CSV·JSON·XLSX, 헤더는 `question,sql,note`(질문/SQL/설명 도 됨) — 「템플릿 CSV」를 내려받아 채우면 됩니다.
아래 「등록된 피드백」에는 인라인 👍/👎 · 이력 편집 · 일괄 등록이 전부 모입니다(출처 배지 INLINE/HISTORY/FEWSHOT). 행마다 삭제, 「프로필 전체 삭제」(확인 모달)로 벡터 인덱스까지 비웁니다.

### 저장 질문 프리셋 (2026-09-29)

「예시 질문 고르기」 드롭다운은 이제 DB 표(`AI_PROMPT_PRESET`)에서 옵니다 — 제목과 질문이 같이 보이고, 고르면 질문과 실행 모드가 입력줄에 들어갑니다. 그 아래 줄에서 **입력줄의 질문을 제목과 함께 「추가」**, 고른 프리셋을 **「수정」·「삭제」** 합니다. 프로필 범위는 이름 패턴이라(`%SH%`), SH 프로필끼리는 같은 프리셋을 봅니다. 처음 27건은 옛 내장 예시를 옮긴 것입니다.

### 실행 모드 7가지

| 모드 | 무엇을 하나 | 언제 |
|---|---|---|
| `showsql` | SQL 만 생성 (실행 안 함) | **시연 기본값.** AI 가 뭘 만드는지 먼저 보여줄 때 |
| `runsql` | SQL 생성 + 실행 + 결과표 | 실제 답을 볼 때 |
| `narrate` | 자연어로 답변 | 표가 아니라 문장으로 |
| `explainsql` | 생성된 SQL 해설 (**한국어**) | "이 SQL 이 왜 이런가" 설명할 때 |
| `showprompt` | LLM 에 실제로 간 프롬프트 | 내부 동작을 보여줄 때 — 반응이 좋은 모드 |
| `summarize` | 결과 요약 | 행이 많을 때 |
| `chat` | 자유 대화 | 스키마와 무관한 질문 |

### 정확도를 올리는 법 — Annotation

「스키마 · Annotation」 서브탭의 **Annotation 적용**을 누르면 컬럼에 의미 설명이 붙습니다(23ai+ 기능).
붙이기 전후로 같은 질문을 해보면 **AI 가 컬럼을 고르는 정확도가 달라지는 것**을 보여줄 수 있습니다.

### 질의 이력 (2026-09-29)

네 번째 서브탭 **「이력」** 은 이 앱이 Select AI 를 부른 기록 전부입니다 — 질문, 후속 버튼, 직접 실행한 `SELECT AI` 까지. 위에 요약 카드(총 질의 · 성공률 · 평균/최대 소요 · 피드백 비율)와 **프로필(모델)별 소요**가 있고, 아래 표는 질문 검색(대소문자 무시) · 기간 · 프로필 · 액션 · 상태 · 피드백으로 거릅니다. 행을 누르면 생성 SQL · 답변 앞부분 · **오류 전문**이 뜹니다 — 화면에서는 "타임아웃"으로만 보이던 실패가 여기서는 `ORA-20429 … HTTP 429` 처럼 원인 그대로 남습니다. 「조회 SQL」을 펼치면 표가 어떤 SQL 로 나왔는지 보입니다.

### 직접 SQL 실행

입력창 아래 작은 `SELECT` 줄에서 SELECT 문을 직접 돌릴 수 있습니다. AI 가 만든 SQL 을 손봐서 재실행할 때 씁니다.

`SELECT AI showsql 고객이 몇 명인가요` 처럼 **Select AI 축약구문도 그대로 됩니다** — SQLcl 에서 치던 문장을 화면에서 재현할 때 쓰세요.
우상단에서 고른 프로필이 적용되고, SQL 블록에 `SELECT AI · 프로필명` 배지가 붙습니다.

> ⚠ **SELECT 로 시작하는 문장만 허용**됩니다(보안). `WITH` 로 시작하는 CTE 도 거부되니,
> CTE 가 필요하면 바깥을 `SELECT * FROM (…)` 로 감싸세요.

### 자주 막히는 곳

| 증상 | 원인·조치 |
|---|---|
| 질문이 오류 (`ORA-20404 Object not found - bearer=…`) | 프로필의 외부 LLM 자격증명·엔드포인트 문제(2026-09-05 GROQ 프로필에서 실측). 프로필을 `GEMINI_SH_PROFILE` 로 바꾸면 됩니다. Groq 는 DB 의 `GROQ_CRED` 자격증명/ACL 을 손봐야 합니다 |
| 엉뚱한 컬럼을 씀 | Annotation 을 적용해 보세요 |
| 응답이 느림 | 외부 LLM 호출 시간입니다(2~4초). DB 쪽 문제가 아닙니다 |

## 1½. Select AI Agent (2026-09-30)

상단 메뉴 **「AI Agent」**. 26ai 의 `DBMS_CLOUD_AI_AGENT` 로 만든 **툴(SQL) · 에이전트 · 태스크 · 팀**이 DB 안의 객체로 있고, `RUN_TEAM` 한 줄이 에이전트에게 질문을 주면 에이전트가 도구를 골라 SQL 을 돌리고 답을 씁니다.

| 서브탭 | 하는 일 |
|---|---|
| **정의** | 객체 4종의 목록과 속성 JSON. **「샘플 팀 만들기」** 가 PL/SQL 4개(툴 → 에이전트 → 태스크 → 팀)를 실행하고 그 문장을 보여줍니다. Agent 는 provider=google 네이티브 프로필이 필요해 `GEMINI_SH_NATIVE` 를 자동으로 만듭니다(OpenAI 호환 엔드포인트로는 마지막 호출이 HTTP 400 — 실측) |
| **실행** | 팀을 고르고 자연어로 묻습니다(1턴 15~25초). 답 아래 **「Thinking」**(툴 호출의 입력→출력), **「단계별 시간」**(태스크·툴 단위 ms, 이 대화 누적), 메타(conversation_id · elapsed · team · multi turn), 👍/👎. Multi Turn 이 켜져 있으면 "그중 …" 이 이어집니다 |
| **Agent History** | `USER_AI_AGENT_TEAM_HISTORY` 기반 표(시작시각 · Team · 질문 · 상태 · 소요 · 피드백 · conversation_id) + 필터. 행을 누르면 단계·툴 호출·답·피드백 편집 |

피드백은 팀이 쓰는 NL2SQL 프로필에 `DBMS_CLOUD_AI.FEEDBACK` 으로 들어가므로, NL2SQL 탭의 이력·Few-shot 화면에도 같이 보입니다.

## 2. AI Vector Search

**문서를 벡터로 바꿔 "의미가 비슷한" 내용을 찾습니다.** 이 탭이 이 앱에서 가장 볼거리가 많습니다.

### 이렇게 써보세요 (권장 순서)

1. **환경** 서브탭(기본 진입) → 「검색 준비 완료」 한 줄 → ① 벡터를 담는 테이블 → ② 모델 카드의 **「VECTOR_EMBEDDING 실행」** (문장 하나가 숫자 768개가 되는 것을 그 자리에서) → ③ 인덱스 2종(만든 문장 펼치기). 카탈로그 원문은 **내부** 서브탭
   → 무엇이 저장되는지 먼저 보여줍니다 (`embedding VECTOR` 컬럼, HNSW·Oracle Text 인덱스)
2. **적재** 서브탭 → PDF 하나 올리기. 끝나면 **단계별 실행 내역**의 라벨을 눌러 실행된 SQL(`UTL_TO_CHUNKS` · `UPDATE … VECTOR_EMBEDDING` · `SYNC_INDEX`)과 표본(청크 3개 · 벡터 앞 8차원)을 펼친다
   → 5단계 파이프라인이 실시간으로 흐릅니다 (등록 → 추출 → 청킹 → 임베딩 → 인덱싱). 임베딩 없이 저장된 청크가 있으면 **경고 배너**가 뜹니다
3. **검색 · RAG** 서브탭 → 입력창 위 세그먼트를 **비교**로 두고 질문
   → 키워드와 벡터 결과가 좌우로 나란히 뜹니다. **여기가 하이라이트입니다**
4. 같은 질문을 **수동 하이브리드**(앱이 SQL 로 가중합) 로, 그리고 **Hybrid Vector Index (26ai)**(인덱스 하나 + `DBMS_HYBRID_VECTOR.SEARCH`, DB 가 융합) 로 다시 —
   청크마다 융합·벡터·텍스트 점수가 붙는다. 후자를 쓰려면 「환경」 탭에서 인덱스를 먼저 만든다(청크 수 × 0.3초)
5. 「내부」 → **실행계획** 카드: 같은 검색을 `WHERE embedding IS NOT NULL` 유무로 EXPLAIN — 술어가 있으면 `TABLE ACCESS FULL`, 없으면 `VECTOR INDEX HNSW SCAN`
   → 청크마다 vector · keyword · hybrid 점수와 V/K 막대가 보입니다
5. 답변 아래 후속 버튼 — `임베딩 과정` · `키워드 비교` · `벡터 인덱스 정보` · `벡터 시각화`(2D 산점도)

### 검색 모드 4가지

| 모드 | 어떻게 찾나 | 특징 |
|---|---|---|
| **의미 검색** | `VECTOR_DISTANCE` 코사인 유사도 | 단어가 달라도 뜻이 같으면 찾음 |
| **키워드 검색** | Oracle Text `CONTAINS` + `SCORE` | 정확한 단어가 있어야 찾음 — 대조군 |
| **하이브리드** (26ai) | 단일 SQL 에서 둘을 결합 | `0.7 × 벡터유사도 + 0.3 × 키워드점수` |
| **비교 모드** | 키워드·벡터 동시 실행 | 좌우 비교. RAG 답변을 만들지 않아 빠름 |

**참조 청크 카드**에 각 청크의 `vector` · `keyword` · `hybrid` 점수가 배지로 보입니다.
하이브리드가 왜 그 순서인지 숫자로 설명할 수 있습니다.

### RAG 답변

의미·키워드·하이브리드 모드는 검색된 청크를 컨텍스트로 **LLM 이 한국어 답변을 생성**합니다.
답변 아래 「참조 문서 청크」가 근거입니다 — 출처를 보여줄 수 있다는 점이 RAG 의 핵심입니다.

### 임베딩 설정 — DB 내장 vs 외부 API

| | DB 내장 (ONNX) | 외부 API |
|---|---|---|
| 어디서 계산 | **Oracle DB 안** | 외부 서비스 |
| 네트워크 | 불필요 | 필요 |
| 시연 포인트 | "임베딩이 DB 안에서 돈다" | 비교용 |

**내부** 서브탭(ONNX 모델 카드) → 모델 행의 **테스트**를 누르면 차원과 소요시간이 나옵니다.
현재 `MULTILINGUAL_E5_BASE`(768차원)를 씁니다.

> ⚠ **알려진 제약**: 차원이 다른 모델(E5_SMALL 384차원)로 바꾼 뒤 PDF 를 올리면 **임베딩이 저장되지 않습니다**
> (HNSW 인덱스가 첫 데이터의 차원으로 고정되기 때문). 새 화면은 인덱스 모델과 현재 모델이 다르면 **경고 배너**를 띄우고,
> 소스를 바꿀 때 Vector Store 초기화를 묻습니다. 순서: 초기화 → 재업로드 — `docs/design/04_DB_설계서.md` 3절.

### 실행 쿼리 확인

**페이지 우상단 「실행 쿼리 확인」은 이 탭에서 꼭 보여주세요.** 방금 화면 뒤에서 돈 SQL 원문이 `V$SQL` 에서 나옵니다. 실행계획은 **내부** 서브탭에 있습니다.
"진짜 SQL 로 도는구나"가 확인되면 데모의 설득력이 크게 올라갑니다.

### 성능 기준값 (2026-09-04 실측, 79청크)

| 항목 | 정상 |
|---|---|
| 의미 검색 SQL | ~95ms |
| 키워드 검색 SQL | ~49ms |
| 하이브리드 SQL | 0.1초대 |
| 비교 모드 (RAG 없음) | 40~70ms |
| 검색 응답 전체 | 3~4초 (**대부분 LLM 답변 생성 시간**) |
| PDF 업로드 (27쪽/79청크) | 약 30초 |

**전체가 3~4초인데 SQL 이 0.1초면 정상**입니다. 나머지는 LLM 입니다.
5초 넘게 걸리는 첫 질의가 있다면 워밍 전일 수 있습니다.

## 3. JSON Relational Duality

**하나의 데이터를 관계형 테이블로도, JSON 문서로도 다룹니다.** 복제본이 없습니다.

### 이렇게 써보세요

1. **Duality View 생성** → `CUSTOMERS_DV`·`PRODUCTS_DV` 생성
2. **관계형 vs JSON 비교** → 같은 데이터가 좌우로
3. **문서 조회 / 수정** → JSON 을 고치고 저장
   → **관계형 테이블이 실제로 바뀝니다.** 이게 Duality 의 핵심입니다
4. **ETag 동시성 제어** → 두 사용자가 같은 문서를 고치는 상황 재현
   → 뒤늦은 수정이 거부되는 것을 보여줍니다
5. 우상단 **실행 쿼리 확인** → 방금 돈 SQL 을 `V$SQL` 에서 봅니다

> 비교 화면의 오른쪽은 **JSON 문서 ↔ 앱 화면** 토글이 있습니다. 앱 화면은 그 JSON 을 프론트엔드가
> 가공 없이 카드로 그린 것 — "백엔드 코드가 필요 없다"는 주장을 눈으로 보여주는 자리입니다.
> ETag 시뮬레이션 4단계의 거부는 흉내가 아니라 **DB 가 직접 낸 ORA-42699** 입니다.

### 왜 중요한가

앱 개발자는 JSON 을 원하고 DBA 는 관계형을 원합니다. 보통은 둘 중 하나를 포기하거나
동기화 코드를 짭니다. Duality View 는 **같은 데이터의 두 얼굴**이라 동기화가 필요 없습니다.

## 4. Property Graph

**기존 테이블 위에 그래프를 정의해 관계를 따라가는 질의를 합니다.** SQL:2023 표준(SQL/PGQ).

### 이렇게 써보세요

1. **그래프 생성** → `SALES_GRAPH` (정점: 고객·제품, 간선: 판매)
2. **SQL vs SQL/PGQ 비교** → 쿼리 3개를 차례로 실행
   → **좌우 결과가 완전히 같아야 정상입니다**
3. **관계 탐색(패턴 매칭)** → MATCH 패턴 질의 3종
4. **시각화** → 패턴 질의 1번 결과를 그래프 그림으로 (간선 굵기 = 매출, 색 = 카테고리)
5. 우상단 **실행 쿼리 확인** → 방금 DB 에서 실제로 돈 SQL 을 `V$SQL` 에서 봅니다

### 비교 쿼리 3종

| # | 질문 | 보여주는 것 |
|---|---|---|
| 1 | 고객 524가 구매한 제품 목록 | 1-hop — JOIN 과 거의 같음 |
| 2 | 제품별 구매 고객 수·총 매출 Top-10 | 집계는 `GRAPH_TABLE` **바깥**에서 |
| 3 | 고객 524와 같은 제품을 산 고객 | **2-hop (고객→제품←고객)** — 추천 시스템의 원리 |

**3번이 이 탭의 하이라이트입니다.** JOIN 으로 쓰면 자기조인이 필요한데, 그래프에서는
`(c1)-[s1]->(p)<-[s2]-(c2)` 로 관계를 그대로 씁니다.

### 왜 중요한가

**데이터 복제가 없습니다.** Neo4j 같은 전용 그래프 DB 는 데이터를 옮겨 담아야 하지만,
Oracle Property Graph 는 **기존 테이블 위의 뷰**입니다. ETL 도, 동기화도 없습니다.

## 5. 개발생산성 향상

**26ai 가 동시성 문제를 어떻게 줄이는지 시뮬레이션으로 보여줍니다.**

| 기능 | 시나리오 | 보여주는 것 |
|---|---|---|
| **Lock-Free Reservations** | 여러 세션이 같은 잔액을 동시에 차감 | 잠금 대기 없이 예약으로 처리. 잔액 부족은 CHECK 제약으로 거부 |
| **Priority Transactions** | 긴급 트랜잭션이 일반 트랜잭션과 충돌 | 우선순위 높은 쪽이 선점 |

각 버튼을 누르면 단계별 SQL 과 결과가 순서대로 표시됩니다.
데모용 임시 테이블을 만들고 끝나면 정리하므로 스키마에 남는 것이 없습니다.

- 단계는 한 칸씩 드러납니다(세션 순서가 곧 내용이라서). 기다리기 싫으면 **[바로 보기]**.
- Priority Transactions 는 Autonomous Database 에서 `PRIORITY_TXNS_MODE` 를 바꿀 수 없어
  **1단계(테이블 생성)만 실제 실행**이고 2~6단계는 동작 설명입니다. 화면에도 그렇게 적혀 있습니다.
- 우상단 **실행 쿼리 확인** → `V$SQL` 에 남은 RESERVABLE·TXN_PRIORITY 관련 SQL 을 봅니다.

## 6. 기타 부가 기능 — AWR 리포트 AI 분석

**실제 Oracle AWR 성능 리포트를 LLM 이 읽고 진단합니다.**

### 이렇게 써보세요

1. AWR HTML 파일 업로드 (최대 20MB)
2. 파싱 → LLM 분석 (30~120초 — 진행 표시는 단계 연출이고 결과는 한 번에 옵니다)
3. **8개 섹션 보고서** + **7개 카테고리 점수(0~100)** + **우선순위별 액션 아이템**
4. **후속 질문**으로 이어서 물어보기
5. **AWR 원문 보기**(배지 행 오른쪽)로 AI 판단의 근거를 원문에서 확인
6. LLM 은 업로드 카드 우상단에서 고릅니다 (Groq · Google). 결과 탭은 여러 개 쌓입니다

### 읽는 법

- **카테고리 점수**: systemLoad · waitEvents · topSql · ioPerformance · hotSegments · memory · hostCpu
  → 낮은 점수부터 보세요
- **액션 아이템**: `[긴급]` / `[높음]` / `[중간]` 순. 각 항목에 **evidence(근거)** 가 붙습니다
- 결과는 탭으로 여러 개 쌓입니다 — 리포트를 비교할 때 유용합니다

> AI 분석은 **출발점이지 결론이 아닙니다.** 액션 아이템의 evidence 를 원문에서 반드시 확인하세요.

### 용어

| 용어 | 뜻 |
|---|---|
| **청크(chunk)** | 문서를 검색 단위로 자른 조각 (약 500자, 50자 겹침) |
| **임베딩(embedding)** | 텍스트를 숫자 벡터로 바꾼 것. 여기서는 768차원 |
| **코사인 유사도** | 두 벡터가 이루는 각도로 재는 의미 유사도. 1에 가까울수록 비슷 |
| **HNSW** | 벡터 근사 최근접 탐색 인덱스. 전수 비교 없이 빠르게 찾음 |
| **RAG** | 검색으로 찾은 근거를 LLM 에 주고 답을 만들게 하는 방식 |
| **SQL/PGQ** | SQL 표준의 그래프 질의 확장 (SQL:2023) |
| **ETag** | 문서 버전 표식. 남이 먼저 고쳤으면 내 수정을 거부 |
