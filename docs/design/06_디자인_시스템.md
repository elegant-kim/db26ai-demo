## 1. 원칙

**investhub 에서 잇는 것 (셋)**
1. **토큰으로만 색을 쓴다.** 컴포넌트에 hex 를 쓰지 않는다. 라이트/다크는 `data-theme` 속성 하나로 갈린다.
2. **타이포 3단 고정** — 카드 제목 16/600 · 소제목 14/600 · 보조 12. 임의값(`text-[15px]`) 금지.
3. **비동기 대기는 "멈춤"과 "작업 중"을 구분한다** — `LoadingBlock` 의 4초/20초 규칙 그대로.

**db26ai 가 더하는 것 (셋)**
4. **SQL 이 주인공이다.** SQL 블록은 어느 테마에서도 같은 다크 터미널 스타일로, 화면에서 가장 먼저 눈에 들어와야 한다.
5. **비교는 나란히.** 두 결과를 놓는 화면은 좌우 대칭이어야 하고, 같은 행이 같은 높이에 온다.
6. **Oracle 브랜드는 액센트와 헤더로만.** 본문·표·카드는 중립색이다. 빨강을 남발하면 오류와 구분되지 않는다(§2.3).

### 2.3 빨강 두 개의 규칙 — 액센트와 오류를 섞지 않는다

Oracle Red(`#C74634`, 벽돌색)와 negative(`#ff3b30`, 선명한 빨강)는 톤이 다르지만 **역할로 더 확실히 가른다.**

| 역할 | 토큰 | 형태 |
|---|---|---|
| 브랜드·활성·주 버튼 | `--accent-primary` | **채움**(버튼 배경, pill 배경 soft, 세로바) |
| 오류·불일치·실패 | `--accent-negative` | **글자·테두리·배지** + 아이콘(`AlertTriangle`/`XCircle`) 동반. 채움은 `-soft` 만 |

→ 화면에서 "빨간 채움 = 브랜드, 빨간 글자+아이콘 = 오류". 오류 상자에 `--accent-primary` 를 쓰지 않는다.

## 5. 컴포넌트 스펙

### 5.1 Card (investhub 그대로)
`padding 24px · radius 8 · border 1px --border-default · shadow --shadow-card · bg --bg-elevated`. 제목 슬롯 = 16/600 + lucide 18.
**db26ai 추가 슬롯:** `actions`(우상단 버튼 영역 — "실행 쿼리 확인" 등). Card 를 고치지 않고 `header` 슬롯으로 구현.

### 5.2 Stat (그대로)
라벨 14 secondary → 값 24/600 tone → 힌트 12 muted. 용도: 매뉴얼>현재 상태의 스냅샷 카드, Vector Store 의 청크/임베딩 수.

### 5.3 Button (그대로)
| variant | 배경/글자 | 용도 |
|---|---|---|
| primary | accent / 흰 | 실행·질문·검색·생성 |
| secondary | surface / primary, 테두리 strong | 취소·보조 |
| ghost | 투명 | 아이콘성 |
| danger | negative / 흰 | 삭제·DROP |
크기 sm `6px 10px 12` · md `8px 14px 14` · lg `10px 18px 15`. 반경 6.
**비활성 = opacity .5 + not-allowed.** 실행 중은 라벨을 "처리 중…" 으로 바꾼다(ConfirmModal 패턴).

### 5.4 Badge (그대로 + 2 tone 추가)
default/primary/positive/negative/warm 에 **`info`**(`--accent-info` 12%)와 **`code`**(mono, `--bg-surface`) 추가.
용도: 소요시간(`53ms`=code), 상태(`VALID`=positive, `LIKE 폴백`=warm, `ORA-…`=negative), 모드(`hybrid`=primary).

### 5.5 ResultTable ★
- 래퍼: `overflow-x:auto`, 최대 높이 `420px` 세로 스크롤(현 `table-wrapper` 계승), 카드 안에서 좌우 여백 0.
- th: 14/600, `--bg-surface`, 아래 테두리 `--border-default`, `position: sticky; top:0`.
- td: 14, 패딩 `8px 10px`, 숫자열 우측 정렬 + `tabular-nums`, 행 hover `--bg-hover`.
- 푸터 행: `N행 · 53ms` (12 muted). 0행이면 EmptyState(§6.2).
- props: `Rows`(05 §4.2) 하나.

### 5.6 SqlBlock ★ (원칙 4)
```
┌ 헤더 bar: [라벨 "실행된 SQL"·mode 배지]           [복사] [줄번호] ┐  h=36, bg --bg-surface, 12px
│ pre: bg --code-bg  text --code-text  13px mono lh1.6  pad 14 16 │
│      키워드 --code-keyword · 함수 --code-fn · 문자열 · 숫자 · 주석  │
│      최대높이 320 → 세로 스크롤, 가로는 wrap 안 함(스크롤)          │
└──────────────────────────────────────────────────────── radius 6 ┘
```
- 라이트·다크 **모두 다크 배경** (`--code-*` 는 테마 무관). 카드 배경과의 대비가 곧 "여기가 SQL" 신호다.
- 하이라이터: 현 `highlightOracleSQL()` 로직을 TS 로 옮기고 색만 토큰으로. (`GRAPH_TABLE`·`VECTOR_EMBEDDING`·`CONTAINS`·`JSON_VALUE` 등 26ai 함수는 `--code-fn`)
- `json` 모드: 같은 껍데기에 JSON 프리티 (Duality).
- **사용자 확인 포인트 ②** — 다크 블록이 라이트 테마에서 무겁게 느껴지면 `--code-bg` 를 `--bg-surface` 로 바꾸는 한 줄로 전환 가능.

### 5.7 CompareView ★ (원칙 5)
`grid lg:grid-cols-2 gap-3 items-start`. 각 열은 슬롯(`left`/`right`)이고 상단에 **열 헤더**: 방식 이름(14/600) + 소요 배지 + 결과 상태 배지(`일치`=positive / `오류`=negative).
두 결과가 같은 행수·같은 값이면 상단에 얇은 `positive-soft` 배너 "두 결과가 동일합니다 (10행)". 다르면 warm 배너 + 차이 요약. **이 배너가 이 앱의 서사를 한 줄로 말한다.**

### 5.8 ChatThread · ChatComposer ★
- 스레드 폭 `max-w-[960px]`. 사용자 말풍선: 우측, `--accent-primary` 배경 흰 글자, radius 12(현 `bubble-user` 계승). 어시스턴트 결과: 좌측, **카드가 아니라 카드 없는 블록**(SqlBlock + ResultTable + 배지 행) — 말풍선 안에 카드를 넣으면 이중 테두리가 된다.
- 결과 블록 하단 액션 행: `ghost sm` 버튼들(실행계획 · 차트 · SQL 복사 · 원문).
- 컴포저(하단 고정): 1행 = 옵션 툴바(프로필 셀렉트 · 실행모드 세그먼트 · 예시 셀렉트) 12px, 2행 = 입력(`--bg-surface`, 테두리 strong, radius 6) + primary 버튼. 로딩 중 버튼 "처리 중…" + 입력 비활성.

### 5.9 PipelineProgress ★ (SSE)
현 `pipeline-*` 계승: 좌측 세로 타임라인(점: 대기 muted / 진행 accent + pulse / 완료 positive), 단계명 14/600 + 소요 12 muted + 상세 12 secondary, 진행 단계에는 `progress-bar`(h 6, radius 999, accent). 완료 후 헤더에 총 소요. **`warning` 필드가 오면 warm 배너**(임베딩 실패 건수 — 절대 숨기지 않는다).

### 5.10 SessionTabs ★

### 5.11 ChunkCard ★

## 6. 상태 표현

### 6.1 로딩 — `LoadingBlock` 규칙 (investhub 그대로)
| 경과 | 표시 |
|---|---|
| 0~4초 | 스피너 + `불러오는 중…`(조회) / `계산 중…`·`분석 중…`(생성) |
| 4초~ | + `(N초)` + **hint** — 왜 걸리는지. db26ai 표준 힌트: "LLM 이 답변을 생성하고 있습니다(2~4초)" / "재기동 직후에는 임베딩 모델 예열로 첫 질의가 5초 걸립니다" |
| 20초~ | `예상보다 오래 걸립니다` warm + 재시도 안내 |

**초기 진입에서 데이터가 비었고 로딩 중이면 반드시 LoadingBlock** — `!loading` 으로 숨기기만 하는 것 금지.
60초 이상 API 를 부르는 버튼(AWR 분석·PDF 업로드)은 `disabled` + 스피너 + 진행 문구.

### 6.2 빈 상태 — `EmptyState`
아이콘(lucide 40, muted) + 한 줄(14 secondary) + **다음 행동**(primary sm 버튼 또는 링크). 예: 검색 결과 0건 → "문서가 없습니다 · [PDF 업로드]". 현 `empty-state` 계승.

### 6.3 오류
`negative-soft` 배경 + `--accent-negative` 좌측 3px + `AlertTriangle` 16 + 메시지 14 + 원문(ORA-…)은 `code` 배지. **오류는 항상 보인다** — 토스트로 흘려보내지 않는다(토스트는 성공 알림 전용).

### 6.4 폴백·경고
`warm` 배너: "Oracle Text 인덱스가 없어 LIKE 로 검색했습니다", "임베딩 3건이 저장되지 않았습니다(ORA-51932)". Phase 1 에서 로그로 살린 경고들은 **화면에서도 같은 문장**으로 나온다.

## 10. 편차 분류 — 사용자 확인의 기준

각 탭 완료 시 새 화면과 기준선 캡처를 나란히 드리고, 편차를 다섯 종류로 표시한다:

| 분류 | 뜻 | 예 |
|---|---|---|
| **A 의도된 편차** | 이 문서가 정한 것 | 헤더 차콜, SQL 다크 블록, 레드 액센트 |
| **B 도메인 편차** | investhub 에 없는 db26ai 고유 요소 | CompareView, StepList(단계 카드), VersusBox(기존 vs 26ai), PipelineProgress(링+단계), KvGrid, SessionTabs, ChatThread/ChatComposer, ChunkCard, GraphViz(SVG 이분 그래프), RecentQueriesPanel(슬라이드 패널) |
| **C 밀도 편차** | 간격·크기가 기준선과 다름 | 카드 패딩이 20 으로 보임 → 수정 |
| **D 색 편차** | 토큰 아닌 색이 섞임 | 옛 `#e0e0e0` 잔존 → 수정 |
| **E 상태 편차** | 로딩·빈·오류 표현이 §6 과 다름 | 스피너만 돌고 안내 없음 → 수정 |

C·D·E 는 제가 고쳐서 다시 드린다. **사용자는 A·B 만 판단하면 된다.**
