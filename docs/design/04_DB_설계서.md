## 2. 앱 테이블

### `DOCUMENTS` — 업로드 문서 메타데이터

```sql
CREATE TABLE documents (
    doc_id       NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    filename     VARCHAR2(500),
    upload_date  TIMESTAMP DEFAULT SYSTIMESTAMP,
    status       VARCHAR2(20) DEFAULT 'processing',   -- processing → indexed
    chunks_count NUMBER DEFAULT 0                     -- 저장된 청크 총수(임베딩 실패분 포함)
);
```

### `DOC_CHUNKS` — 청크 + 임베딩 벡터

```sql
CREATE TABLE doc_chunks (
    chunk_id    NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    doc_id      NUMBER NOT NULL,
    chunk_text  CLOB,
    source_file VARCHAR2(500),
    page_num    NUMBER,
    embedding   VECTOR          -- 차원 무제약. 차원을 고정하는 것은 인덱스다(아래 참조)
);
```

> `doc_id` 에 FK 제약이 없다. 문서 삭제는 `delete_document()`가 두 테이블을 함께 지운다.

## 3. 인덱스

| 인덱스 | 타입 | 대상 | 정의 위치 |
|---|---|---|---|
| `DOC_CHUNKS_HNSW_IDX` | **VECTOR** | `doc_chunks(embedding)` | `vector_search.py: init_vector_tables()` |
| `DOC_CHUNKS_TEXT_IDX` | **DOMAIN** (Oracle Text) | `doc_chunks(chunk_text)` | `sql/setup/50_oracle_text_index.sql` |
| `SYS_C00364xx` | NORMAL | 각 테이블 PK | 자동 |
| `SYS_IL0000...$$` | LOB | `chunk_text` CLOB | 자동 |

```sql
-- 벡터 인덱스 (기동 시 자동 생성)
CREATE VECTOR INDEX doc_chunks_hnsw_idx ON doc_chunks(embedding)
ORGANIZATION INMEMORY NEIGHBOR GRAPH
DISTANCE COSINE
WITH TARGET ACCURACY 95;

-- 전문검색 인덱스
CREATE INDEX doc_chunks_text_idx ON doc_chunks(chunk_text)
INDEXTYPE IS CTXSYS.CONTEXT
PARAMETERS ('LEXER CTXSYS.WORLD_LEXER SYNC (ON COMMIT)');
```

### ⚠ HNSW 인덱스가 벡터 차원을 고정한다

`embedding VECTOR` 컬럼 자체는 차원 무제약이지만, **HNSW 인덱스는 처음 들어온 데이터의
차원으로 고정**된다. 차원이 다른 벡터를 INSERT 하면 `ORA-51932: Mismatched dimension count`.

**임베딩 모델 교체 절차:**
1. 기존 청크 삭제 (`DELETE FROM doc_chunks`)
2. `DROP INDEX doc_chunks_hnsw_idx`
3. `.env` 의 `EMBEDDING_MODEL` 변경 → 서버 재기동 (기동 시 인덱스가 비어 있는 상태로 재생성됨)
4. 문서 재적재 → 새 차원으로 인덱스가 고정된다

> **미해결 부채**: 사이드바의 런타임 임베딩 전환은 이 절차를 밟지 않아, 전환 후 업로드하면
> 임베딩이 전부 NULL 이 된다. `docs/SESSION_HANDOFF.md` 열린 과제 1번.

### Oracle Text 렉서 선택

`WORLD_LEXER` 를 쓴다. 데모 문서가 한글 본문에 영문 기술용어가 섞인 형태라
기본 `BASIC_LEXER`(공백 분리)로는 부적합하다. `SYNC (ON COMMIT)` 이라 업로드 커밋 즉시 검색 가능.

> `WORLD_LEXER` 는 한글 조사를 분리하지 않는다 — `인덱스`(11건)와 `인덱스를`(2건)이 서로 다른
> 토큰이다. 그래서 앱은 질의를 `to_contains_query()` 로 어간+우측절단 ACCUM 구문으로 변환한다.

## 6. Property Graph

```sql
CREATE PROPERTY GRAPH sales_graph
VERTEX TABLES (
    admin.customers KEY (cust_id) PROPERTIES (...),
    admin.products  KEY (prod_id) PROPERTIES (...)
)
EDGE TABLES (
    admin.sales KEY (prod_id, cust_id, time_id, channel_id, promo_id)
        SOURCE KEY (cust_id) REFERENCES customers (cust_id)
        DESTINATION KEY (prod_id) REFERENCES products (prod_id)
        PROPERTIES (amount_sold, quantity_sold, time_id)
);
```

**기존 테이블 위의 뷰라 데이터 복제가 없다.** 간선 KEY 는 `SALES` 에 PK 가 없어
복합키를 쓴다(2026-09-04 수정 — 그전에는 `rowid`).

> **SQL/PGQ 제약**: `GRAPH_TABLE()` 의 `COLUMNS` 절 안에서 집계함수를 쓸 수 없다
> (`ORA-49011`). 원시 행을 투영하고 바깥에서 집계한다.

## 8. 알아둘 Oracle 제약

| 제약 | 내용 |
|---|---|
| `ORA-22849` | `VECTOR` 컬럼에 집계함수 직접 사용 불가 → `COUNT(CASE WHEN embedding IS NOT NULL THEN 1 END)` |
| `ORA-51932` | HNSW 인덱스 차원 불일치 (위 3절 참조) |
| `ORA-49011` | `GRAPH_TABLE()` 안 집계함수 |
| `ORA-29902` | 자연어 문장을 `CONTAINS` 에 직접 전달 (`?` 등이 예약 연산자) |
| LOB | `hasattr(row[0], 'read')` 체크 후 `await _lob_to_str(val)` |
| DDL bind | DDL 에 bind variable 사용 불가 → 문자열 포맷팅 + 이스케이프 |
| `VECTOR_EMBEDDING` | 모델명은 SQL identifier — bind 불가, f-string 삽입. **항상 스칼라 서브쿼리로 감쌀 것**(100배) |
